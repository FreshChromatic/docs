---
title: Chunks, ranges, biomes, and structures
description: Understand ChunkRevive target selection and coordinate units.
---

ChunkRevive first builds a target set, then regenerates, resets, or deletes that set. Marking does not modify terrain immediately.

## Selection methods

| Method | Best for | Main command |
| --- | --- | --- |
| Current chunk | A one-point test | `/cr mark here` |
| Explicit chunk | Automation or remote targets | `/cr mark chunk <world> <cx> <cz>` |
| Follow | Manual selection while walking | `/cr mark follow` |
| Radius | Existing chunks around a centre | `/cr mark radius ...` |
| Full-world scan | Existing persisted chunks in one or all worlds | `/cr mark fullmark ...` |
| Biome | A biome ID or current contiguous biome | `biomefull`, `biomeradius`, `here biome` |
| Structure | A detected complete structure group | `/cr struct ...` |

## Three coordinate systems

| Parameter | Unit |
| --- | --- |
| `x`, `z` | Block coordinates |
| `cx`, `cz` | Chunk coordinates |
| `rx`, `rz` | Anvil region coordinates |

A chunk is 16×16 blocks. An Anvil region is 32×32 chunks, or 1,024 positions.

## Existing chunks

Disk scans use `scan.min-persisted-status` to decide which chunks are fully written; the default `FULL` avoids selecting incomplete generation states.

## Complete regions

Prune is not enabled merely because a selection is “almost full”. The Reset planner requires:

- Exactly the 1,024 positions of one region.
- No missing or duplicate positions.
- No Residence claim or protected structure blocking it.

If that test fails, the strategy uses Delete Chunk or Regen instead; it does not truncate the entire region.
